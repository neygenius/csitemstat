# Проект CSItemStat Bot — документация

## 1. Общая цель и назначение

**CSItemStat Bot** — это Telegram‑бот для отслеживания цен предметов из инвентаря Steam. Он позволяет пользователям:

- Загружать свой инвентарь Steam и добавлять интересующие предметы в персональный **портфель**.
- Получать актуальную информацию о ценах: минимальная, медианная, объём продаж за 24 часа.
- Смотреть графики исторической цены за различные периоды (7, 30, 90 дней и всё время).
- Настраивать **процентные ценовые алерты** (при изменении цены на заданный процент за 24 часа или 7 дней).
- Подписываться на **ежедневные** или **еженедельные** дайджесты по каждому предмету.
- Управлять всеми подписками и алертами через удобный интерфейс инлайн‑кнопок.

Приложение представляет собой **монолит** на базе FastAPI, работающий в режиме **webhook** для приёма обновлений от Telegram. Внутри того же процесса запущен планировщик **APScheduler**, который периодически собирает данные из Steam Web API и рассылает уведомления.

## 4. Схема базы данных (PostgreSQL)

Приложение использует 7 таблиц. Все связи – через внешние ключи с каскадным удалением (`ON DELETE CASCADE`).

### 4.1 Таблица `users`
Хранит информацию о пользователях Telegram.

| Поле        | Тип                  | Описание                                      |
|-------------|----------------------|-----------------------------------------------|
| `id`        | BIGINT PRIMARY KEY   | Telegram `user_id`                            |
| `chat_id`   | BIGINT NOT NULL      | ID чата для отправки сообщений                |
| `steam_id64`| BYTEA                | Зашифрованный SteamID64 (Fernet)              |
| `created_at`| TIMESTAMPTZ          | Дата регистрации (по умолчанию NOW())         |

**Связи**: `tracked_items` → `UserTrackedItem`, `subscriptions` → `Subscription`, `price_alerts` → `PriceAlert`.

### 4.2 Таблица `items`
Справочник предметов Steam.

| Поле               | Тип                  | Описание                                    |
|--------------------|----------------------|---------------------------------------------|
| `id`               | SERIAL PRIMARY KEY   | Идентификатор                               |
| `app_id`           | INTEGER NOT NULL     | ID приложения (по умолчанию 730 – CS:GO)    |
| `market_hash_name` | TEXT NOT NULL        | Уникальное имя предмета на маркете          |
| `name`             | TEXT                 | Человекочитаемое название (необязательно)   |
| `icon_url`         | TEXT                 | URL иконки (необязательно)                  |
| `is_tracked`       | BOOLEAN DEFAULT false| Флаг для массового отслеживания (зарезервирован)|

**Ограничения**: уникальность по `(app_id, market_hash_name)`.

**Связи**: `tracked_by` → `UserTrackedItem`, `daily_stats` → `ItemDailyStats`, `hourly_stats` → `ItemHourlyStats`, `snapshot` → `ItemSnapshot`, `subscriptions` → `Subscription`, `price_alerts` → `PriceAlert`.

### 4.3 Таблица `user_tracked_items`
Связь «многие ко многим» между пользователями и предметами (портфель пользователя).

| Поле      | Тип                  | Описание                          |
|-----------|----------------------|-----------------------------------|
| `user_id` | BIGINT PRIMARY KEY   | Внешний ключ → `users.id`         |
| `item_id` | INTEGER PRIMARY KEY  | Внешний ключ → `items.id`         |
| `added_at`| TIMESTAMPTZ          | Дата добавления в портфель        |

**Индексы**: по `user_id` для быстрых запросов.

### 4.4 Таблица `item_daily_stats`
Дневная агрегированная статистика цен и объёмов.

| Поле      | Тип                  | Описание                                   |
|-----------|----------------------|--------------------------------------------|
| `item_id` | INTEGER PRIMARY KEY  | Внешний ключ → `items.id`                  |
| `date`    | DATE PRIMARY KEY     | Дата                                       |
| `price`   | NUMERIC(10,2)        | Медианная цена за день (в валюте Steam)    |
| `volume`  | INTEGER NOT NULL     | Количество проданных единиц за день        |

**Индексы**: по `(item_id, date)` для быстрых выборок.

### 4.5 Таблица `item_hourly_stats`
Почасовая статистика цен (используется для построения графиков и расчёта изменений).

| Поле        | Тип                  | Описание                                   |
|-------------|----------------------|--------------------------------------------|
| `item_id`   | INTEGER PRIMARY KEY  | Внешний ключ → `items.id`                  |
| `timestamp` | TIMESTAMPTZ PRIMARY KEY| Время записи (с точностью до часа)         |
| `price`     | NUMERIC(10,2)        | Цена в этот час                             |
| `volume`    | INTEGER NOT NULL     | Количество продаж за час                    |

**Индексы**: по `(item_id, timestamp)`.

### 4.6 Таблица `item_snapshot`
Актуальный снимок состояния предмета (обновляется каждые 30 минут).

| Поле               | Тип                  | Описание                                        |

| `lowest_price`     | NUMERIC(10,2)        | Минимальная цена на данный момент                |
| `median_price`     | NUMERIC(10,2)        | Медианная цена                                   |
| `volume_24h`       | INTEGER              | Объём продаж за 24 часа                          |
| `price_24h_ago`    | NUMERIC(10,2)        | Цена 24 часа назад (из часовых или дневных данных)|

| `trend_direction`  | TEXT                 | `up` / `down` / `stable`                        |
| `updated_at`       | TIMESTAMPTZ          | Время последнего обновления                     |

**Индексы**: по `updated_at`.

### 4.7 Таблица `subscriptions`
Подписки на периодические дайджесты.

| Поле           | Тип                  | Описание                                      |

| `user_id`      | BIGINT NOT NULL      | Внешний ключ → `users.id`                     |
| `item_id`      | INTEGER NOT NULL     | Внешний ключ → `items.id`                     |
| `frequency`    | TEXT NOT NULL        | `daily` или `weekly`                          |
| `active`       | BOOLEAN DEFAULT true | Активна ли подписка                           |
| `last_sent_at` | TIMESTAMPTZ          | Дата последней отправки дайджеста             |
| `created_at`   | TIMESTAMPTZ          | Дата создания                                 |

**Ограничения**: уникальность по `(user_id, item_id, frequency)`.

### 4.8 Таблица `price_alerts`
Процентные ценовые алерты.

| Поле               | Тип                  | Описание                                      |
|--------------------|----------------------|-----------------------------------------------|
| `id`               | SERIAL PRIMARY KEY   | Идентификатор                                 |
| `user_id`          | BIGINT NOT NULL      | Внешний ключ → `users.id`                     |
| `item_id`          | INTEGER NOT NULL     | Внешний ключ → `items.id`                     |

| `active`           | BOOLEAN DEFAULT true | Активен ли алерт                              |
| `last_triggered_at`| TIMESTAMPTZ          | Время последнего срабатывания (cooldown 1 час)|
| `created_at`       | TIMESTAMPTZ          | Дата создания                                 |

## 5. Ключевые методы и принципы работы

### 5.1 Авторизация в Steam и получение данных

- **`SessionManager`** (`app/services/steam/session_manager.py`) управляет жизненным циклом сессии Steam.  
  - При первом запуске выполняет логин с использованием `username`, `password` и `.maFile` (Steam Guard).  
  - Сериализованная сессия сохраняется в Redis (ключ `steam:session:tokens`) с TTL, заданным в `STEAM_SESSION_TTL`.  
  - При последующих запросах сессия восстанавливается из Redis; если куки устарели, выполняется `refresh_access_token` и `obtain_cookies`.

- **`SteamProvider`** (`app/services/steam/provider.py`) реализует интерфейс `ISteamProvider` на базе `aiosteampy`.  
  - Метод `get_price_overview` получает текущую цену через публичный API (с возможностью fallback на прямой HTTP-запрос при ошибке).  
  - `get_price_history` возвращает историю цен за всё время (используется для синхронизации).  
  - `get_inventory` получает инвентарь пользователя по `steam_id64`.

- **`SteamClient`** (`app/services/steam_client.py`) – фасад, добавляющий **RateLimiter** (20 запросов в минуту).  
  - Используется **токен-бакет** с корректным обновлением времени, что гарантирует соблюдение лимитов Steam API.

### 5.2 Сбор и обновление данных (планировщик)

**Задачи в `scheduler/jobs.py`**:

| Задача                  | Расписание           | Описание |
|-------------------------|----------------------|----------|
| `update_snapshots_job`  | Каждые 30 минут      | Обновляет `item_snapshot` и `item_daily_stats` для всех отслеживаемых предметов (поочерёдно). |
| `check_alerts_job`      | Каждые 30 минут      | Проверяет активные алерты и отправляет уведомления при достижении порога. |
| `daily_digest`          | Каждый день в 10:00  | Отправляет ежедневные дайджесты. |
| `weekly_digest`         | Каждый понедельник в 10:00 | Отправляет еженедельные дайджесты. |
| `history_sync_job`      | Каждый день в 02:00  | Синхронизирует историю цен (часовые и дневные данные) для всех предметов. |

**Обновление снапшота** (`collector.update_snapshots`):
1. Выбираются все предметы, у которых есть хотя бы один трекер.
2. Для каждого предмета:
   - Запрашивается `price_overview` через SteamClient.
   - Парсится цена (функция `parse_steam_price` – устойчива к различным форматам).
   - Обновляется/создаётся запись в `item_snapshot`.
   - Добавляется/обновляется дневная статистика (`item_daily_stats` за сегодня).
   - Вычисляется тренд (`statistics.compute_trend`) и сохраняется в снапшот.
   - Определяется цена 24 часа назад (из `item_hourly_stats` или вчерашней `item_daily_stats`).

### 5.3 Процентные алерты

При создании алерта пользователь задаёт процент и период (`24h` или `7d`).  
В задаче `check_alerts_job` для каждого активного алерта:
- Если период `24h` – используется `snapshot.price_24h_ago`.
- Если `7d` – выполняется запрос к `item_daily_stats` за последние 7 дней, берётся ближайшая доступная цена (если точная дата отсутствует).
- Вычисляется изменение: `(current - old)/old * 100`. Если модуль изменения >= заданного процента – отправляется уведомление.  
- **Cooldown**: алерт не срабатывает чаще чем раз в час (поле `last_triggered_at`).

### 5.4 Дайджесты

Задачи `daily_digest` и `weekly_digest` выбирают активные подписки с соответствующей периодичностью.  
Для каждой подписки формируется сообщение с текущей ценой, изменением за период и направлением тренда.

### 5.5 Работа с инвентарём и портфелем

- Команда `/inventory` загружает инвентарь пользователя через `SteamClient.get_inventory`, группирует предметы по `market_hash_name` и кэширует в Redis на 5 минут (ключ `inv:{user_id}`).  
- Пагинация реализована через callback-запросы; данные берутся из кэша.
- Добавление предмета в портфель (`/track` или кнопка "➕ Отслеживать") создаёт запись в `user_tracked_items`.

### 5.6 Графики цен

Команда `/stats` или кнопка "📊 Статистика" вызывает `send_price_chart`, которая:
- Выбирает часовые (`item_hourly_stats`) или дневные (`item_daily_stats`) данные за указанный период.
- Генерирует PNG-график через `plotter.generate_price_chart` (matplotlib + seaborn).
- Отправляет фото в Telegram с кнопками выбора периода (7, 30, 90 дней, всё время).

### 5.7 Управление сообщениями (CleanupManager)

`CleanupManager` хранит в Redis списки `message_id` для каждого чата и категории (например, `temporary`).  
При отправке временных сообщений (подсказки, инвентарь, портфель) они регистрируются.  
При следующем вызове команды или при переходе по страницам старые сообщения удаляются, чтобы не засорять чат.  
**Важно**: графики не удаляются (целенаправленное решение), чтобы пользователь мог вернуться к ним.

### 6.2 Запуск с использованием Docker Compose

В проекте присутствует `docker-compose.yaml`, который поднимает два сервиса:

```yaml
services:
  db:    # PostgreSQL 15
  redis: # Redis 7-alpine
```

Приложение можно запустить отдельно (например, через `uvicorn`) или добавить сервис `app` в `docker-compose` (Dockerfile не предоставлен, но предполагается его наличие).

**Локальный запуск без Docker**:

1. Установить зависимости: `pip install -r requirements.txt`
2. Запустить PostgreSQL и Redis локально (или через `docker-compose up -d db redis`).
3. Создать базу данных и применить миграции (Alembic, если настроен).
4. Запустить приложение: `uvicorn app.main:app --host 0.0.0.0 --port 8000`.

> Приложение автоматически установит вебхук при старте (lifespan). Для локального тестирования без HTTPS можно использовать Cloudflared или аналоги.

## 7. Известные ограничения и план улучшений

### 7.1 Текущие ограничения

- **Последовательное обновление снапшотов** – каждый предмет обновляется по очереди, что при количестве > 500 предметов может превысить 30-минутный интервал.
- **Отсутствие слоя репозиториев** – SQL-запросы разбросаны по обработчикам и сервисам, что затрудняет тестирование.
- **Интеграционные тесты** – покрыты только юнит-тесты с моками; реальное взаимодействие с БД и Redis не проверяется.
- **Планировщик работает в том же процессе**, что может влиять на отзывчивость вебхука при высоких нагрузках.
- **Нет мониторинга** – отсутствуют метрики времени выполнения задач, количества запросов к Steam, ошибок.
- **Документация команд** – часть команд (`/subscribe`, `/alert`) перенаправлены на вспомогательные сообщения, их функциональность доступна только через `/bagpack`.

### 7.2 План по улучшению (To‑Do)

1. **Параллелизация обновления снапшотов** – использовать `asyncio.gather` с семафором для ускорения, контролируя лимиты Steam.
2. **Выделение слоя репозиториев** – создать `UserRepository`, `ItemRepository` и т.д., чтобы упростить тестирование и поддерживать единообразие запросов.
3. **Интеграционные тесты** – добавить тесты с использованием `testcontainers` для PostgreSQL и Redis.
4. **Вынос планировщика в отдельный процесс** – при росте нагрузки запускать `scheduler` как отдельный микросервис или использовать Celery.
